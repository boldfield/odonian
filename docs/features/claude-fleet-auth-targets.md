# Claude fleet authentication Make targets

## Requested behavior

Add make claude-auth and make claude-auth-check, matching the convenience of existing codex-auth and codex-auth-check. Reuse CP_CONTEXT and FLEET_NAMESPACE, currently admin@summercamp-cp and odonian-fleet. The live worker and reviewer deployments both inject CLAUDE_CODE_OAUTH_TOKEN from secret claude-oauth, key token. Keep Claude subscription authentication through claude setup-token. Do not change billing/auth mode, deployments, replica counts, model routing or existing Codex targets.

The owner subsequently requested direct implementation instead of Odonian; both registered implementation tasks were retired. Implementation is in the local Makefile and deploy/fleet/claude_auth.py. Creating/testing the commands does not authorize rotating real credentials, restarting live pods or making paid model calls. A read-only fleet synchronization check is permitted.

## Update target

make claude-auth obtains a newly generated setup-token value, validates that it is present and a single non-whitespace token, updates or creates the claude-oauth Secret and then restarts both deployment/worker and deployment/reviewer. Wait for both rollouts with bounded timeouts and report failures as failures. Never restart if credential reading, validation or Secret update failed. Report partial success explicitly if Secret replacement succeeds but a subsequent rollout fails. Re-running should safely retry.

Token sources are, in order: an explicitly supplied CLAUDE_AUTH_TOKEN_FILE path, the existing CLAUDE_CODE_OAUTH_TOKEN environment variable, or a hidden interactive terminal prompt. An explicitly selected missing/empty/unreadable file is an error, not a reason to fall back to another credential. For automated use, support file/env input without prompting. When neither is provided and no terminal is available, fail with the setup-token and input instructions. Do not scrape local Claude credentials or Keychain; they are a different authentication path. Do not automate browser login. A helper script called by a short Make recipe is appropriate for reliable shell error handling and secret management.

Never interpolate the token through Make expansion, command-line arguments, shell tracing, echoed recipes, logs, Git or readable persistent temporary files. Feed secret content via stdin or a permission-restricted temporary file with cleanup on success/failure/signals. Do not print raw Kubernetes secret YAML, decoded values, hashes/fingerprints or credential-bearing error output. There must be no kubectl command whose printed arguments include the token. Do not instruct users to pass a token as a make command-line variable; use the prompt, protected file or inherited environment instead. Ensure dry-run Make output cannot expand or reveal an inherited token. Secret update must preserve unrelated keys/metadata where applicable, and must not delete/recreate the Secret. Do not modify GitOps workload specifications.

After successful restarts, invoke the read-only check once it exists. This target's invocation authorizes those two restarts; do not add another approval prompt. Before restarting, explain that pod replacement can interrupt in-flight work; document that operators should choose an appropriate window. The merger and Odonian server do not consume this credential and must not be restarted.

## Check target

make claude-auth-check is read-only: no login, Secret writes, rollouts, task changes or inference calls. Check that the configured Kubernetes API is reachable, Secret/key exists and is nonempty, and that worker/reviewer deployments refer to the expected Secret/key. Distinguish RBAC/network errors, missing resources, missing/empty key, wrong references, zero replicas, missing/unready pods, stale loaded token and healthy synchronization.

Inspect the relevant non-terminating worker/reviewer containers and compare their injected CLAUDE_CODE_OAUTH_TOKEN with the stored Secret without returning either plaintext token. A supported in-container digest/compare command is acceptable, but keep derived fingerprints internal and print only match/mismatch/unknown with pod/container identity. Skip neither old/new pods in a rolling update nor a mismatching replica while declaring all pods synchronized. Do not use printenv to return the credential. If runtime inspection is forbidden/unavailable, report runtime synchronization as unknown and exit nonzero rather than treating it as success. No token-shaped inputs belong in kubectl exec arguments. Use available standard fleet tooling and document needed get/exec RBAC.

If file/env token input is supplied, also compare it with the cluster Secret without printing either; without it, report local comparison as not requested rather than prompting or failing. Explicitly configured unreadable input is an error. Handle scaled-to-zero deployments honestly as no running credential verified. A successful check means configured credentials are present and loaded consistently, not that the provider accepted them or that subscription allowance remains. Do not infer expiry from token shape, compare Codex last_refresh fields, or claim that claude auth status proves validity. Finish with a concise statement that live provider authentication was not tested. Document checking the next real dispatch for provider acceptance; a separate live probe is outside this small feature.

Return nonzero for mismatch, missing required state, failed/unverifiable runtime inspection or transport errors. Keep output short and useful with explicit context/namespace and actionable recovery instructions, never secrets.
